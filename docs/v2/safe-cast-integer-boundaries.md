# Safe-Cast and Integer-Width Boundaries (V2-SC-161)

Solidity's explicit `uintN(x)` conversion never reverts: it keeps the low `N` bits of `x`. A
timestamp, amount, counter, weight, chain id, or version identifier that is narrowed this way can
therefore wrap silently (for example `uint64(2**64) == 0`). This document is the authoritative
inventory of every narrowing cast and packed integer field in canonical V2, the valid range and unit
of each narrowed value, and the proof or guard that keeps it lossless. It maps every acceptance
criterion of V2-SC-161 to reproducible evidence.

## Policy

1. **Every narrowing cast is proven safe or guarded.** A cast is *proven safe* only when its operand
   is already bounded by a prior check, a compile-time constant, an enum ordinal, or a same-width
   byte conversion. Every other narrowing goes through
   [`V2SafeCast`](../../contracts/v2/libraries/V2SafeCast.sol).
2. **Clock and chain-id narrowing is always guarded.** Raw `uintN(block.timestamp)`,
   `uintN(block.chainid)` and `uintN(block.number)` are forbidden in canonical V2; the static gate
   rejects them even if someone adds an inventory entry.
3. **Fail closed with a field-identifying error.** Out-of-range values revert with
   `V2Errors.SafeCastOverflow(bytes32 field, uint256 value, uint256 max)`; negative signed inputs to
   an unsigned field revert with `V2Errors.SafeCastNegative(bytes32 field, int256 value)`. `field` is
   a left-aligned ASCII literal such as `"Claims.createdAt"`, and `max` is `type(uintN).max` of the
   destination, so the violated bound is identified deterministically from revert data alone.
4. **No storage-layout change.** Only cast *expressions* changed. Every stored field keeps its type,
   width, order, and slot, so existing deployments and the storage-layout manifests are unaffected.

### Error ABI

| Error | Selector preimage | Raised when |
| --- | --- | --- |
| `SafeCastOverflow` | `SafeCastOverflow(bytes32,uint256,uint256)` | `value > type(uintN).max` for the destination width |
| `SafeCastNegative` | `SafeCastNegative(bytes32,int256)` | `value < 0` converted to an unsigned field |

## Scope

Canonical V2 for this audit is: `contracts/v2/**` (modules, interfaces and fixtures, libraries),
`contracts/governance/v2/**`, `contracts/upgrade/**`, `contracts/verification/**`,
`contracts/performance/**`, `contracts/libraries/**`, and `contracts/ClaimRegistry.sol` (the claim
registry `EvidenceRegistry` reads `createdAt` / `verificationDeadline` from). Legacy V1 contracts
listed in [`contracts/LEGACY_V1.md`](../../contracts/LEGACY_V1.md) — `reward/`, `settlement/`,
`disputes/`, non-v2 `governance/`, root V1 contracts — plus mocks and tests are out of scope
(non-goal: legacy V1 expansion).

## Inventory of narrowing casts

Generated by `node scripts/check-safe-casts.mjs --report` and pinned in
[`config/safe-cast-inventory.json`](../../config/safe-cast-inventory.json).

**Totals:** 58 narrowing-cast occurrences in scope before this change. 32 raw clock/chain-id
narrowings were replaced with `V2SafeCast` calls (newly guarded). 26 occurrences at 20 sites are
proven safe. The 8 bounded conversions inside `V2SafeCast` are the only casts classified `guarded`.
After the change the gate tracks 34 occurrences at 28 distinct sites. No signed (`intN`) conversion
exists in scope.

## Packed integer fields and their ranges

Fields that are narrower than 256 bits are written only from equally-narrow typed inputs, from
guarded casts, or from validated parameters — never from an unchecked narrowing.

| Struct / field | Width | Unit | Valid range | Written from |
| --- | --- | --- | --- | --- |
| `IV2Types.Claim.createdAt` (+ `status` packed) | uint64 | Unix s | `[0, 2^64-1]` | `V2SafeCast.timestamp64` |
| `IV2Types.Evidence/Verification/Dispute/Settlement` time fields | uint64 | Unix s | `[0, 2^64-1]` | typed interface values |
| `EvidenceRegistry.EvidenceCommitment.committedAt` (+ `status`) | uint64 | Unix s | `[0, 2^64-1]` | `V2SafeCast.timestamp64` |
| `IModuleRegistry.ModuleInfo.major/minor` | uint16 | version | `[0, 65535]` | typed `protocolVersion()` return; ABI decoder rejects wider values |
| `IModuleRegistry.ModuleInfo.activatedAt/changedAt` | uint64 | Unix s | `[0, 2^64-1]` | `V2SafeCast.timestamp64` |
| `Claims.claimSpamWindow`, `_claimWindowStart` | uint64 | seconds / Unix s | `(0, 2^64-1]` | constant or typed governance input; window arithmetic is compared in uint256 |
| `ClaimRegistry.Claim.createdAt/verificationDeadline` | uint64 | Unix s | `deadline ∈ (now, now + 365 days]` | guarded clock; typed deadline; horizon compared in uint256 |
| `V2Lifecycle.ParameterSet` amount fields (`minBounty` … `challengeBond`) | uint128 | asset base units | `min <= max` | typed governance input, `validateParameterSet` |
| `V2Lifecycle.ParameterSet` bps fields | uint16 / uint24 | bps | `[0, 10_000]` (appeal multiplier `> 0`) | typed governance input, `validateParameterSet` |
| `V2Lifecycle.ParameterSet` durations / cooldowns | uint48 | seconds | `> 0` | typed governance input, `validateParameterSet` |
| `ReputationWeightedVotingBounds.VotingWeightInput` bps fields | uint16 / uint24 | bps | cap `<= 10_000`, multiplier `> 0` | typed input; weights computed in uint256 via `Math.mulDiv` |
| `IConsumerGuarantees.ConsumerGuarantees` depths / class | uint64 / uint8 | blocks / enum | `V2Guarantees.validate` bounds | typed input |
| `ProtocolUpgradeManager.Version.major/minor/patch` | uint64 ×3 | semver | `[0, 2^64-1]` each | typed input; `_encode` packs into disjoint 64-bit lanes at offsets 128/64/0, so no two components overlap |
| `TruthBountyGovernanceToken` checkpoints | uint48 key / uint208 value | Unix s / votes | supply `<= 2^208-1` | guarded `clock()`; OZ `ERC20ExceededSafeSupply` caps supply |
| `TruthBountyGovernor` `voteStart` / snapshot | uint48 | Unix s | `[0, 2^48-1]` | OZ `SafeCast.toUint48` |

Amounts, rounds, nonces, claim ids, and stake/weight accumulators are `uint256` end-to-end in every
canonical module, so they are never narrowed; the lifecycle tests assert they round-trip at
`type(uint128).max` / `type(uint256).max`.

## Boundary hardening beyond casts

Two uint64 *arithmetic* sites could previously overflow (panic `0x11`) near `type(uint64).max`
instead of evaluating their bound. Both are now compared in uint256 with otherwise identical
semantics:

* `AntiGriefing.nextClaimWindow`: `nowTs >= windowStart + window`.
* `ClaimRegistry.createClaim`: `verificationDeadline > now_ + MAX_DEADLINE_HORIZON`.

## Storage compatibility and migration

No stored field changed type, width, order, or slot: only cast expressions and two comparisons
changed, so `storage-layouts/manifest.json`, `config/storage-layouts.json`, and the V2-SC-046
validator are unaffected. No migration is required.

Every guarded uint64 field holds Unix seconds up to year ~5.8 × 10^11, and the uint48 governance
clock up to year ~8.9 × 10^6; no valid value is excluded today. If a future release needs a wider
range, the governed path is: (1) add a new wider field in an append-only storage slot of a new
implementation; (2) submit the upgrade through `ProtocolUpgradeManager` with a storage-compatibility
attestation and migration hash (`validateMigration`); (3) back-fill from the narrow field, which is
lossless because every stored value was bounds-checked on write. The narrow field is never
re-typed in place.

## Running the checks

```
node scripts/check-safe-casts.mjs            # inventory + guard anchors
node scripts/check-safe-casts.mjs --report   # print detected cast sites
node --test test/scripts/check-safe-casts.test.mjs
forge test --match-path "test/v2/SafeCastBoundaries.t.sol"
```

A new narrowing cast in canonical V2, a changed occurrence count, a raw `block.timestamp` /
`block.chainid` narrowing, a stale entry, or a removed guard fails CI until the inventory is updated
deliberately with a bound and justification.

## Impact notes

* Contracts whose ABIs now include `SafeCastOverflow` (every module that calls `V2SafeCast`) gain one
  error entry; no function, event, or selector changed.
* Guarded sites add one comparison per narrowing; `.gas-snapshot` may need regenerating with
  `forge snapshot` for the touched modules.
